## 🚦 Verdict

✅ **GO release — wp.org round-2 ready.** All five findings from the 2026-05-17 reviewer email are addressed:

1. **Code-bearing files in uploads** (HtmlImport) — `extract_zip_to_uploads()` refactored: `.html` / `.htm` / `.js` zip entries are NEVER written to disk. The index HTML is read in memory via `ZipArchive::getFromName()` and stored in `post_content`. Only CSS / images / fonts / json / txt / map extract to disk.
2. **Text domain ≠ slug** — text domain `variolab` → `variolab-ab-testing` everywhere (354 occurrences across 14 PHP files).
3. **`$_POST['url_scripts']` still flagged by AI** — refactored. Output now goes through `wp_print_inline_script_tag()` (the WP-blessed inline-script helper), no longer a raw `echo`. New `UrlScripts::parse_script_input()` silently strips `<script ...>` wrappers and extracts `src` / `async` / `defer` / `type` / `id` attributes. Intake remains `unfiltered_html`-gated.
4. **`Router.php` raw output** — same root cause as #3, fixed by the refactor: `Router::print_scripts_*` no longer `echo`s.
5. **Generic prefixes** (≥4 chars required) — CPT `ab_experiment` → `abtest_experiment`, menu slug `ab-testing` → `abtest-experiments`. Idempotent migration runs at upgrade from DB <1.4.0.

PHPCS 32/32 green (one new flag — `Squiz.PHP.CommentedOutCode` on a re-worded comment — fixed during the audit). PHPUnit **108 tests / 518 assertions** green (+11 new `UrlScriptsTest` covering plain JS / single wrapper / multi-script degraded / orphan tag / boolean attribute branches). `composer audit` = 0 CVE. Dependabot = 0 open alerts.

## Step 2 — Situated checklist (v0.14.0 deltas highlighted)

### A. `admin_post_*` handlers — ✅ (unchanged from v0.13.0)
All 8 handlers verify `current_user_can('manage_options')` + `check_admin_referer(...)`. The `url_scripts` save in `Admin\Admin::handle_save()` retains the `unfiltered_html` capability gate (v0.13.0) AND now stores codes that will be wrapped at output via `wp_print_inline_script_tag()` (v0.14.0). Comment block (Admin.php:324-336) rewritten to describe the new flow.

### B. REST endpoints — ✅ (unchanged)
- `POST /abtest/v1/convert` — `permission_callback: __return_true` (intentional public), dedup + 60/min/IP rate-limit, `$_SERVER['REMOTE_ADDR']` sanitized at intake (v0.13.0).
- `GET /abtest/v1/stats` — `current_user_can('manage_options')`, args schema with validate/sanitize callbacks per param.

### C. File upload + zip extraction — ✅ **HARDENED in v0.14.0**

The `extract_zip_to_uploads()` refactor is the biggest security delta in v0.14.0:

**Before (v0.13.0)**: single pass extracted every allowed entry (incl. `.html` / `.htm` / `.js`) to disk under `uploads/abtest-templates/{slug}/`. The index HTML was then read from disk and rewritten.

**After (v0.14.0)**: 2-pass design.
- **Pass 1**: walks zip entries metadata-only, locates the preferred `index.html` (root match first, else first `.html` found). Never opens a stream.
- **Pass 2**: extracts only non-code asset extensions (`css/png/jpg/jpeg/gif/svg/webp/avif/woff/woff2/ttf/otf/ico/json/txt/map`). `.html` / `.htm` / `.js` are deliberately skipped.
- The index HTML body is pulled into memory via `ZipArchive::getFromName($index_relpath)` (line 444) — **never written to disk**. The body is rewritten in memory (relative URLs → absolute), then returned for storage in `post_content`.

Security filter `zip_entry_is_safe()` extracted into a private helper (HtmlImport.php:385-401), called in BOTH passes. Same checks as before: rejects absolute paths, `..` traversal, dotfiles, `__MACOSX/`, directory entries.

Upstream upload allowlist (`ALLOWED_EXTS = ['html', 'htm', 'zip']`) unchanged — admins can still upload single `.html` / `.htm` files (which go directly to `post_content`) or `.zip` archives (now narrower extraction).

**Functional regression** acknowledged in commit message + readme.txt v0.14.0 entry: templates that reference local JS via `<script src="./bundle.js">` will 404 at render. Admins can re-inject inline JS via the per-URL tracking-scripts feature.

### D. SQL — ✅ **+1 NEW MIGRATION**

New idempotent migration in `Plugin::pre_install_rename_post_type()` (Plugin.php:113-122) — uses `$wpdb->prepare()` with `%s` placeholders for both the new and legacy post_type values. Second run matches 0 rows. Runs at upgrade from DB <1.4.0 via `maybe_upgrade_schema()`, fires at `plugins_loaded` BEFORE the CPT registers on `init` so subsequent queries find the renamed rows.

All other `$wpdb->prepare()` usages unchanged from v0.13.0.

### E. Cookies + hashing — ✅ (unchanged)
Cookie flags (`secure: is_ssl()`, `httponly: true`, `samesite: Lax`, TTL 30d) and `visitor_hash` (SHA-256 + `wp_salt('auth')`, truncated to 16 chars / 64 bits) unchanged. `$_SERVER` reads still sanitized via `sanitize_text_field(wp_unslash())` (v0.13.0).

### F. Outbound HTTP — ✅ (unchanged)
GA4 + Webhook integrations unchanged. `sslverify: true` explicit. Anti-SSRF protocol check (`^https?://`) on webhook URLs.

### G. WP-Cron + filesystem — ✅ (unchanged)
Watcher scans only `$uploads['basedir'] . HtmlImport::ASSETS_SUBDIR`. With v0.14.0 dropping `.js` / `.html` from zip extraction, the Watcher will see fewer file types under that path — no security impact, just narrower scope.

### H. Direct file access + bootstrap — ✅

All PHP files start with `defined('ABSPATH') || exit;` (verified across 27 files in `includes/` + `variolab-ab-testing.php`). Main file `variolab-ab-testing.php` only registers hooks at require time. Activation/deactivation hooks idempotent. `uninstall.php` gated by `defined('WP_UNINSTALL_PLUGIN') || exit;` — now accepts both `'abtest_experiment'` and the legacy `'ab_experiment'` so old installs that skipped the v1.4.0 upgrade still get cleaned up cleanly.

### I. Consent gate (GDPR) — ✅ (unchanged)
Default OFF preserved. Filter `abtest_visitor_has_consent` must return strictly `true` to allow tracking. Admin/bot bypass exempt. 5 unit tests cover the 4 gate states.

### J. Per-URL tracking scripts — ✅ **REFACTORED in v0.14.0**

The biggest output-side delta:

**Before (v0.13.0)**: `UrlScripts::render_for_position()` returned a concatenated string of every stored entry's `code`. Router echoed this via raw `echo` with a `phpcs:ignore WordPress.Security.EscapeOutput.OutputNotEscaped`.

**After (v0.14.0)**: `UrlScripts::print_for_position()` is **void** — iterates entries, parses each via `parse_script_input()`, and calls `wp_print_inline_script_tag($body, $attrs)` per entry. Router has zero `echo` calls and zero `phpcs:ignore` lines for this surface.

`parse_script_input()` handles 3 input shapes:

1. **Plain JS body** — passthrough, no attrs.
2. **Single `<script ...>...</script>` wrapper** — regex extracts attrs + body. Sanity-checks the body doesn't still contain another `<script>` tag (multi-script case); falls through to (3) if it does.
3. **Multi-script / orphan tag / mixed** — degraded mode: regex strips every `<script ...>` and `</script>` from the input. Bodies concatenate. Attrs are lost (admins should split such snippets across multiple entries for clean fidelity).

`parse_script_attrs()` extracts quoted key/value pairs (single OR double quotes) plus boolean bare-word attributes (`async`, `defer`, `nomodule`). Keys are lowercased; values passed verbatim to `wp_print_inline_script_tag()` which is responsible for safe rendering.

11 new unit tests in `tests/Unit/UrlScriptsTest.php`:
- Plain JS pass-through (1)
- Plain JS trimmed (1)
- Wrapper without attrs (1)
- Wrapper with `src` + `async` (1)
- Wrapper with `defer` + `type` (1)
- Wrapper with `id` (1)
- Multi-script degraded mode (1)
- Orphan opening tag (1)
- Single quotes in attrs (1)
- Boolean attribute as bare word (1)
- Empty input (1)
