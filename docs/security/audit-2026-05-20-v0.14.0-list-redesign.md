> Pre-push regression audit of the list-page redesign branch. The branch is 5 commits ahead of `main` plus an in-progress brand-shell extraction + brand-header rollout across the four admin pages (Edit / Settings / HtmlImport / List). Goal: catch any regression introduced by the redesign vs the v0.14.0 baseline (10/10, 0 findings) on `main` before pushing the branch.
>
> **Scope of deltas reviewed** :
> - 4 new WOFF2 fonts in `assets/fonts/` (Inter Tight + JetBrains Mono, Latin subset, ~200 KB total).
> - 3 new stylesheets: `admin-tokens.css` (CSS custom properties + `@font-face`), `admin-shell.css` (shared brand shell), `admin-list.css` (list-page styles).
> - 1 new JS: `assets/js/list-interactions.js` (~200 LOC vanilla, inline SVG sparkline renderer).
> - 3 deleted assets: `assets/js/url-charts.js`, `assets/js/vendor/chart.umd.min.js`, `assets/js/vendor/README.md`.
> - 1 new PHP helper: `Stats::overview_kpis()` (pure-PHP aggregator on existing batched SQL).
> - 1 new shared helper: `Admin::render_brand_header( $title, $right_actions = '' )`.
> - Full rewrite of `includes/Admin/ExperimentsList.php` (≈600 LOC → ≈700 LOC; new render flow with KPI strip / toolbar chips / URL blocks / SVG sparklines / archived `<details>`).
> - `ExperimentEdit.php`, `Settings.php`, `HtmlImport.php` now wrap in `.wrap.vlab-page.abtest-wrap` (dual class — old form-table styles preserved) and call `Admin::render_brand_header()` at the top.
> - New shell-CSS enqueue order (`vlab-admin-tokens` → `vlab-admin-shell` → `abtest-admin` → optional `vlab-admin-list` on list page only).

## 🚦 Verdict

✅ **GO push — no regression vs v0.14.0 baseline.** The redesign is purely a presentation-layer refactor: no new SQL, no new admin-post handler, no new REST endpoint, no new file-upload surface, no new outbound HTTP, no new external dependency. Every new echo path uses `esc_html` / `esc_attr` / `esc_url`. The one `innerHTML` in `list-interactions.js` is fed exclusively from server-controlled values (palette hexes, JSON-encoded series, escapeXml'd text). The dual `.vlab-page.abtest-wrap` class on Edit / Settings / Import keeps every legacy form-table style alive, so no functional regression on form submission paths.

The branch can be pushed and merged into `main`. Version bump (0.14.0 → 0.15.0) + new audit + tag should happen at the next release cycle, not now.

## Step 2 — Situated checklist (deltas highlighted)

### A. `admin_post_*` handlers — ✅ (unchanged)
Every one of the 8 handlers still verifies `current_user_can('manage_options')` + `check_admin_referer(...)`. The brand-header rollout only swaps the `<h1>` for `Admin::render_brand_header( $title )` — it doesn't touch the submission paths. Sticky-form transient stash logic preserved.

### B. REST endpoints — ✅ (unchanged)
- `POST /abtest/v1/convert` — `__return_true` (intentional public, dedup + rate-limit).
- `GET /abtest/v1/stats` — `check_permission` (`manage_options`).

### C. File upload + zip extraction — ✅ (unchanged from v0.14.0)
The `zip_entry_is_safe()` helper + 2-pass extraction (in-memory index HTML, only CSS/images/fonts to disk) is exactly as audited at v0.14.0. No code touched in this branch.

### D. SQL — ✅ **+1 NEW pure-PHP helper, NO new query**

`Stats::overview_kpis( int[] $experiment_ids, string $from, string $to )` is a fold over the existing batched query `raw_counts_for_experiments()` — no new SQL. The migration `Plugin::pre_install_rename_post_type()` (v0.14.0) is unchanged.

The list-page rewrite still routes every query through the existing helpers: `Stats::raw_counts_for_experiments()`, `Stats::compute_multi()`, `Stats::daily_breakdown_for_url()`, `Experiment::get_status()`, etc.

### E. Cookies + hashing — ✅ (unchanged)

### F. Outbound HTTP — ✅ (unchanged)

### G. WP-Cron + filesystem — ✅ (unchanged)
The Watcher and Scheduler are unchanged. The font conversion tool (`tools/build-fonts.sh`) is a local-dev artifact excluded from the .zip by `release.yml`'s `--exclude='/tools/'` filter — never runs at WordPress runtime.

### H. Direct file access + bootstrap — ✅
Verified 27 PHP files under `includes/` + the main `variolab-ab-testing.php`: all start with `defined('ABSPATH') || exit;` (within the first 40 lines — ExperimentsList.php now has a ~30-line docblock so the guard sits at line 36, hence the 30-line `head` window in the previous v0.14.0 audit needed widening for this branch).

### I. Consent gate (GDPR) — ✅ (unchanged)

### J. Per-URL tracking scripts — ✅ (unchanged at the storage layer; rendering still via `wp_print_inline_script_tag` in Router.php)

## Notes / non-findings for context

- The redesign visually unifies the 4 admin pages but the **form-table on Edit / Settings / Import is unchanged** — those screens still rely on the legacy `admin.css` rules via the dual `.wrap.vlab-page.abtest-wrap` class. No security-relevant change to the form submission paths.
- The list page's new query arg `?status_filter=all|draft|running|paused|ended` is read with `sanitize_key()` and validated against an allowlist (`self::chip_statuses()`) before use. Old `?show=running` is silently translated for one release; same hardening.
- The new `Admin::render_brand_header()` is **public** (vs the previous private `ExperimentsList::render_page_header()`). That's intentional — it's the shared helper called from 4 pages. No data input; pure rendering.
- `list-interactions.js` uses `innerHTML` (one site). Acceptable because every value interpolated into the SVG string is either: server-emitted via `wp_json_encode()`, a hardcoded SVG attribute, a numeric coordinate, a palette hex string, or pre-escaped via `escapeXml()`. No DOM-clobbering surface.
